## Credentials — read carefully

- `CLOUDFLARE_API_TOKEN` in `.env` is the **worker bearer token** (used as `Authorization: Bearer` against the platform worker). Wrangler rejects it.
- `CLOUDFLARE_API_URL` is the worker **root** (no `/api/v1`) — internal routes hang off it directly (`/query`, `/kv/get`, `/kv/put`), while public/service routes need the `/api/v1/…` prefix (`/api/v1/connectors`, `/api/v1/crm/leads`). Hitting `/crm/leads` without the prefix falls through to the internal guard → `{"error":"unauthorized"}` — a misleading 401 that looks like an auth failure but is really a path bug.
- `CLOUDFLARE_DEPLOY_TOKEN` is the real Cloudflare REST token — map it into `CLOUDFLARE_API_TOKEN` for wrangler deploys only.
- GitHub/Brevo/SignWell keys live in KV as `conn:*` (credential-guarded, 403 via HTTP) with `.env` fallbacks.
- `DASHBOARD_SESSION_TOKEN` + `DASHBOARD_PASSPHRASE` in `.env`; login sets the `lazynext_session` cookie. Optional TOTP: `flag:two_factor` + `2fa:secret` in KV — **verified E2E** (no code→`{totp:true}`, bad code→401, valid SHA1/6-digit/30s window±1→`{ok:true}`+session). **LIVE since 2026-09-28 — the founder deliberately enrolled (Google Authenticator "Lazynext: Admin"); do NOT delete these keys** — `flag:two_factor` gates every login incl. the founder's and removing `2fa:secret` orphans the enrollment. Deletion route if ever intentionally disabled: `POST /kv/delete` (`/kv/del` is not a route).
- Never print secret values; reference env vars in commands instead.

## Fleet safety gates (all proven with live catches — keep them)

1. **Protected files** — `worker.js`, `index.html`, `src/scanner.js`, `package.json`, `test/scanner.test.mjs`, and `.github/` (devops role only) are skipped in both the cloud writer (`worker/src/index.ts`) and local `core/tools/code_writer.py`.
2. **Test gate** — `node --test` runs before commit locally; cloud test artifacts require a real exec-container verdict, no LLM fallback. `.mjs` maps to the js checks.
3. **Fitness check** — LLM task-fit review in `CodeWriter._fitness_check` rejects nonexistent references / wrong hosts / off-task code. LLM outage warns and allows; tests + CI are the backstop.
4. **Revert on failure** — `_revert_files` restores tracked files (`git checkout HEAD`), deletes new files, prunes empty dirs. Without it, blocked writes poison later test runs.
5. **Branch per task** — every task forks fresh from `main` (`GitManager.create_pr_branch_and_commit`), commits as `[task_id] desc`, pushes, opens a PR, repo returns to `main`.
6. **Task dedup** — content-word overlap + substring over ALL statuses in the last 24h **plus a persistent dead corpus**: terminal `failed`/`escalated` rows carrying `retired:`/`obsolete:`/`infeasible:`/`closed:`/`resolved:`/`Deliverable `/`phantom_completion:` markers stay dedup-visible forever (`closed:`/`resolved:` are operator annotations for shipped-out-of-band work — the class is dead even though the row predates the corpus markers; `deferred:` deliberately stays OUT — a pending business decision must resurface, and suppressing it would block the post-decision proposal) (`DEAD_CORPUS_WHERE` in `worker/src/index.ts`, mirrored in `cto_agent._get_recent_tasks` — a phantom row escaping the corpus respawns past the 24h window, observed 2026-09-26: 24 launchdeck-type rows cycling). Ordinary failures keep the 24h window so legit retries aren't suppressed. Exact-match-only dedup lets paraphrases respawn forever. **Corpus cap must cover the corpus** — the read is `LIMIT 10000` in both mirrors (raised 2026-09-28 from 2000: corpus 1388 growing ~250 tombstones/day was ~2.5d from overflow); when it was 500 the corpus (1296 rows) silently evicted the oldest dead classes and they respawned (measured 2026-09-27: 327/328 kills in a day matched evicted rows). **Dedup runs BEFORE the infeasible kill-list** in both insert paths (`operate()` and the `cto_agent` decompose loop): a respawn of a dead class now dedup-skips with zero rows written, whereas filter-first wrote a fresh tombstone per paraphrase — that tombstone flood is what overflowed the cap. First-time dead ideas still get the filter + tombstone (the anchor must exist). If the corpus ever approaches the cap again, raise the cap — never narrow the markers. **Resurrection trap:** dedup only gates *new inserts* — `agentTick`'s retry requeue (`failed AND attempts<3 → pending`) must also exclude `DEAD_CORPUS_WHERE` rows, and `TaskTracker.create_task`'s update path must carry `attempts>0` onto existing rows, or a marked-dead task silently re-executes (observed: dead CDN task re-ran → PR #89, 4th recurrence). Word overlap is **stemmed** (`wordsRelated`/`words_related` in both mirrors): the shorter word's first `min(len,5)` chars as shared prefix — "track"/"tracking", "analyze"/"analyzing" count as the same word while "report"/"repository" stay distinct. The `infeasible:` kill-list is **deliverable-gated** — patterns require a build-verb adjacent to the dead noun, so "sales outreach targeting mobile app developers" survives while "build a mobile app" dies. Never widen a pattern to a bare noun — the ungated version had a 100% false-positive rate on native-app kills (measured 2026-09-25); regression set pinned in `tests/unit/test_infeasible_filter.py`. **Kill-class anchor dedup (added 2026-09-28):** word-overlap dedup only catches near-identical paraphrases — divergent rewordings of a dead class slip `inter < threshold`, re-die on the same kill-list label, and each wrote a fresh tombstone (~137 rows/day, dominated by `section 508` + `audit-report doc churn` — the corpus stayed under cap but the flood never actually stopped). Before writing a kill tombstone, both insert paths now check `result LIKE 'infeasible: {label} (%' OR error_log LIKE 'infeasible: {label} (%'` — the label IS the class name, so one anchor row covers every paraphrase (worker writes the marker to `error_log`, the local mirror to `result` — check both). The ` (` terminator prevents label-prefix collisions; fail-open on query error writes the row. First-time kills still anchor; repeats cost a read, not a row. Ordering pinned by `tests/unit/test_dedup_before_filter.py::test_kill_class_anchor_check_precedes_tombstone`.
7. **Workflow-fix dedup** — `find_by_description("run {id}")` across all statuses; only `main`/`master` failures create fix tasks (PR-branch failures belong to the branch author). `get_failed_workflows` also scopes the runs query to the repo's default branch (GitHub `branch` param via cached `/repos/{owner}/{repo}` lookup, `main`/`master` post-filter fallback), so PR-branch runs never reach the monitor's failure list or the fix-fallback's `limit=1` pick — the in-loop branch re-check is belt-and-suspenders.
8. **Phantom-completion gate** — `BaseAgent.handle_task` vetoes `success` between `post_task_hook` and `on_success` when the result *claims* file artifacts (line-start `File: path` markers, a leading code fence, or a `/pull/N` URL) but carries no write evidence (`[Files written:`, `[Committed to git]`, `[Pushed to remote]`, `git_branch`). A bare PR URL is a claim, NOT evidence — hallucinated and real links are text-identical, and every real PR is preceded by a commit our hooks mark (three bare-URL phantoms — 661808ac/5ff7cd78/4723feb3, all citing closed-unmerged PRs — slipped the old regex; corrected 2026-09-27 and the URL was moved claim-side). The write hooks append that evidence only when `code_writer` actually lands files, so claim-without-evidence = a code blob that never shipped. ~200 rows minted `completed` this way before the gate (corrected to `failed` + `phantom_completion:` in error_log, 160-char evidence prefix preserved). The error string is a `_DETERMINISTIC_VETO_MARKERS` member, so 5 consecutive phantoms die `failed`/`infeasible:` — dead-corpus-visible — without QA/HR noise. Auditing old rows: `result` containing ```` ``` ```` fences or `/pull/` links while `status='completed'` — verify the cited PR merged / claimed file exists before believing the row. `code_writer.infer_filename` deliberately returns `None` for FastAPI/React-shaped code (no such stack in either repo) rather than filing it under a ghost `app/` tree.
9. **Retry error feedback** — `BaseAgent._inject_last_error` appends the previous attempt's error (incl. the `node --test` output tail, phantom-import specifier, fitness-review text) to `_injected_context` before attempts 2–4. Without it the retry prompt never saw *what* failed — measured behavior was 5 identical blind attempts per escalated task. The engineering agents fold the gate detail into `result.error` so `error_log` and `mark_escalated` carry actionable text, not just "tests failed".
10. **One fleet process** — restart with `pkill -f run_agents.py` (not `pgrep | head -1`); multiple processes race the queue and defeat dedup. The fleet is launchd-supervised: `com.lazynext.fleet` (KeepAlive, 30s throttle) runs `.venv/bin/python scripts/run_agents.py` with the repo as WorkingDirectory so pydantic finds `.env`; logs at `/tmp/lazynext-fleet.log`. `pkill` IS the restart — KeepAlive respawns exactly one. **Do not** start a manual instance after pkill (that's the two-fleet race). `com.lazynext.healthcheck` runs `scripts/health_check.py` every 15 min. launchd invokes python directly, never a bash wrapper — bash spawned by launchd has no Desktop TCC grant (exit 126 "Operation not permitted"). **launchd PATH trap:** the fleet's PATH is `/usr/bin:/bin:/usr/sbin:/sbin` — `node`/`npm`/`npx`/`pytest` in Homebrew prefixes are invisible, and a bare `create_subprocess_exec("node", ...)` raises FileNotFoundError which the test gate treated as "tool absent → skip". Every subprocess must resolve binaries through `core/tools/bin_resolver.find_binary` (PATH + `/opt/homebrew/bin` + `/usr/local/bin`). `git` is safe (`/usr/bin/git`).
11. **Doc-gutting guard** — overwriting an existing repo file while keeping under half of its non-empty lines is rejected as destruction, not an update (`retainedLineFraction` in `worker/src/index.ts` before `verifyArtifact`; `_retained_line_fraction` in `code_writer.py` before `safe_write`; existing file must be ≥800 chars). Verified live 2026-09-27: a devops task "optimized Cloudflare Worker config" by replacing the measured perf-baseline doc with generic prose (PR #95 closed unmerged) — a size-ratio check would have passed it, since prose replaced dense tables at similar length. Rejected tasks get feedback to extend in place or deliver a new file; the failed deliverable gets a `retired:` dead-corpus marker so the class doesn't respawn. Same class closed in `bootstrapRepo`: on the repo-already-exists (422) path, generated scaffold skips any file that already exists rather than overwriting it. Regressions pinned by `tests/unit/test_doc_gutting.py` and `worker/test/artifact-guard.test.mjs` (the mjs lifts the shipped `retainedLineFraction` source from `index.ts`, so it can't drift).
