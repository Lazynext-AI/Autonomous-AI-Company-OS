## Credentials — read carefully

- `CLOUDFLARE_API_TOKEN` in `.env` is the **worker bearer token** (used as `Authorization: Bearer` against the platform worker). Wrangler rejects it.
- `CLOUDFLARE_DEPLOY_TOKEN` is the real Cloudflare REST token — map it into `CLOUDFLARE_API_TOKEN` for wrangler deploys only.
- GitHub/Brevo/SignWell keys live in KV as `conn:*` (credential-guarded, 403 via HTTP) with `.env` fallbacks.
- `DASHBOARD_SESSION_TOKEN` + `DASHBOARD_PASSPHRASE` in `.env`; login sets the `lazynext_session` cookie. Optional TOTP: `flag:two_factor` + `2fa:secret` in KV — **verified E2E** (no code→`{totp:true}`, bad code→401, valid SHA1/6-digit/30s window±1→`{ok:true}`+session). The flag is **global** — while set it gates every login incl. the founder's; delete both keys after testing (`POST /kv/delete` — `/kv/del` is not a route).
- Never print secret values; reference env vars in commands instead.

## Fleet safety gates (all proven with live catches — keep them)

1. **Protected files** — `worker.js`, `index.html`, `src/scanner.js`, `package.json`, `test/scanner.test.mjs`, and `.github/` (devops role only) are skipped in both the cloud writer (`worker/src/index.ts`) and local `core/tools/code_writer.py`.
2. **Test gate** — `node --test` runs before commit locally; cloud test artifacts require a real exec-container verdict, no LLM fallback. `.mjs` maps to the js checks.
3. **Fitness check** — LLM task-fit review in `CodeWriter._fitness_check` rejects nonexistent references / wrong hosts / off-task code. LLM outage warns and allows; tests + CI are the backstop.
4. **Revert on failure** — `_revert_files` restores tracked files (`git checkout HEAD`), deletes new files, prunes empty dirs. Without it, blocked writes poison later test runs.
5. **Branch per task** — every task forks fresh from `main` (`GitManager.create_pr_branch_and_commit`), commits as `[task_id] desc`, pushes, opens a PR, repo returns to `main`.
6. **Task dedup** — content-word overlap + substring over ALL statuses in the last 24h **plus a persistent dead corpus**: terminal `failed`/`escalated` rows carrying `retired:`/`obsolete:`/`infeasible:`/`Deliverable ` markers stay dedup-visible forever (`DEAD_CORPUS_WHERE` in `worker/src/index.ts`, mirrored in `cto_agent._get_recent_tasks`). Ordinary failures keep the 24h window so legit retries aren't suppressed. Exact-match-only dedup lets paraphrases respawn forever. The `infeasible:` kill-list is **deliverable-gated** — patterns require a build-verb adjacent to the dead noun, so "sales outreach targeting mobile app developers" survives while "build a mobile app" dies. Never widen a pattern to a bare noun — the ungated version had a 100% false-positive rate on native-app kills (measured 2026-09-25); regression set pinned in `tests/unit/test_infeasible_filter.py`.
7. **Workflow-fix dedup** — `find_by_description("run {id}")` across all statuses; only `main`/`master` failures create fix tasks (PR-branch failures belong to the branch author).
8. **One fleet process** — restart with `pkill -f run_agents.py` (not `pgrep | head -1`); multiple processes race the queue and defeat dedup. The fleet is launchd-supervised: `com.lazynext.fleet` (KeepAlive, 30s throttle) runs `.venv/bin/python scripts/run_agents.py` with the repo as WorkingDirectory so pydantic finds `.env`; logs at `/tmp/lazynext-fleet.log`. `pkill` IS the restart — KeepAlive respawns exactly one. **Do not** start a manual instance after pkill (that's the two-fleet race). `com.lazynext.healthcheck` runs `scripts/health_check.py` every 15 min. launchd invokes python directly, never a bash wrapper — bash spawned by launchd has no Desktop TCC grant (exit 126 "Operation not permitted").

- **`/kv/get` was POST-body only** — GET requests 404'd at the method guard, and a `.get('value')` parser prints `None` on the error JSON — which looks exactly like "key missing"/mass data loss. Now accepts `GET ?key=` too (read-only, internal-token gated). Prefer it for ops reads.

This is how you trace vanished rows — a `DELETE FROM task_log` no longer leaves zero forensic trace.
- **`/kv/put` expires writes in 60s by default** — `expirationTtl: Math.max(ttl ?? 60, 60)`. Any ops write without a ttl silently vanishes a minute later. Pass `"ttl": 0` (JSON number, not `"0"` string — `"0" === 0` fails and gets the 60s floor) for a persistent write. Webhook/`billing.ts` writes use explicit TTLs and are unaffected.

- **`wcag-2.1.2`** has five layers: `checkFocus` (rendered scans) uses the real keyboard focus trace (≥4 consecutive Tabs on one element = trap); `scanKeyboardStatics` (all string-scan paths) catches markup-visible trap mechanisms — inline `onkey*` handlers preventDefaulting Tab, `<dialog open>` with no focusable/Escape dismiss, plus `wcag-2.4.3` positive tabindex (F44); and `checkFocusDepth` (`src/rules/focuscycle.js`, rendered scans) uses the deepened `/render` trace — adaptive Tab budget (24 presses normally; census 25–40 focusables gets `focusable+2` presses so coverage is provable; >40 keeps 24 since coverage is unprovable anyway) + a focusable census + an Escape probe — to catch *cycles* (Tab looping among a subset), *coverage gaps* (focusables never reached — guarded to only fire when `trace.length >= focusable` so short traces on big pages stay inconclusive), and *dialogs that ignore Escape*. The trace also presses **Shift+Tab×8** (`backtrace`) — a stall ≥4 mid-order (excluding `body`, the first forward-focused element = natural boundary, and the forward endpoint/cycle members = already owned by the forward checks) or a backward tail-cycle flags a retreat trap. And it **clicks up to 4 likely triggers** (`aria-haspopup`, `data-*-toggle`, non-submit `<button>`s — submit-in-form skipped, JS dialogs auto-dismissed, navigation → `goBack`, stuck dialog → probing stops): a `dialog`/`alertdialog` that appears with focus left outside flags `wcag-2.4.3`, while focus-inside + dead Escape + zero focusable controls flags `wcag-2.1.2` (reachable controls = compliant containment, not flagged; a dialog already open before the click ends probing — attribution would be unsafe). All three deep probes (Escape, backtrace, click suite) are skipped when the census finds zero focusables or the forward trace hard-stalls ≥4 — the trap signature is already established, and ~20 websocket round-trips inside a trapped page buy nothing; backtrace also early-exits on reaching `body` or the first forward element (both excluded downstream) or a completed 2-cycle tail. `role="dialog"` regions are intentionally skipped in the static checks — can't be bounded without a parser. Trace entries carry the element's census index (`idx:tag#id:text`) — same-label siblings ("Get started" ×5) would otherwise collapse into false coverage gaps. Trap-positive fixtures: `trap.html` (real Tab-hijack cycle — flags 2.1.2 + 2.4.3, its Shift+Tab-swallow correctly deduped as the same trap) and `trap2.html` (click-activated dialogs — flags 2.4.3 focus-outside + 2.1.2 hard trap); both in `STATIC_FILES` via `sync-page.mjs`.

Fixture links must be **relative** (`nav-b.html`, never `/nav-b.html` — absolute escapes the `/accessibility-checker/` subpath → 1-page crawl), and fixture text must not literally contain the keywords a check scans for (a page describing "no breadcrumb, aria-current" trips its own regex). Quota key is `rl:scan:<public-ip>:<day>` in the shared KV — ops can delete their own via `POST /kv/delete` for re-verification (get IP via checkip.amazonaws.com).
- **`wcag-1.3.2` / `wcag-2.4.8` (warn-class)** — 1.3.2 flags order-breaking CSS (`order`, reversed `flex-direction`, `bidi-override`) + `aria-flowto` statically; 2.4.8 flags nav pages lacking any wayfinding signal (breadcrumb/aria-current/sitemap) — site-wide gaps collapse to ONE finding, inconsistent pages flag per-page. Trap-positive fixtures: `partial-obscured.html` (2.4.12), `nav-a.html`/`nav-b.html` (2.4.8) — all in `STATIC_FILES` + robots-disallowed.
- **`/render` latency profile (measured 2026-09-25)** — the ruleset is ~3-7ms; the cost is websocket round-trips to the managed browser (~0.5s each): keyboard presses + `page.evaluate` per iteration. `handleRender` merges the per-Tab read into ONE evaluate (entry label + 2.4.11 occlusion + 2.4.13 indicator) and early-exits on a ≥4-press stall or full focusable coverage (subset cycles never reach full coverage → still get all 24 presses). Backtrace exits on ≥4-stall. `launchBrowser` (scrape.ts) reuses idle sessions via `puppeteer.sessions()` + `connect`, falls back to `launch(keep_alive: 120s)`, and `releaseBrowser` `disconnect()`s so the session stays warm. Result: minimal page ~9s (was 48-64s), heavy page ~30-55s — inherent to real Tab probing. If editing the trace loop, keep the merged probe — splitting it back doubles render latency.
- **Priming `seq:last_run` has a one-tick lag** — a KV get can serve the edge-cached pre-prime value for one tick, so the sweep fires on the *second* tick after priming, not the first. Transient, self-correcting — don't mistake it for a dead sweep; check `mon:last_sweep`.
- **Dead-man heartbeat is `cron:last_tick`** (ms epoch, written every scheduled event via `ctx.waitUntil`) — `GET /kv/get?key=cron:last_tick` proves cron is firing; ~10 min behind wall-clock is healthy.
- **Score formula** — `100·e^(−n/15)` (0 issues = 100, 10 ≈ 51, 30 ≈ 14). Was `100−10n`, which pinned at 0 for any site with 10+ findings and deadened drop alerts.
- **Report exports** — `/report/:id.csv` (local, quoted-cell CSV) and `/report/:id.pdf` (proxies platform `/pdf` → Browser Rendering `page.pdf`); both live on the product worker + mirror, linked from the report HTML.

- **Product worker names** — `accessibility-checker` (canonical) and `accessibility-checker-api` (legacy mirror) are **distinct scripts**; deploy changes to both or the mirror drifts.

## Product worker deploys

`accessibility-checker` has no wrangler.toml — deploy with `node scripts/deploy.mjs` inside `products/accessibility-checker` (env: `CLOUDFLARE_DEPLOY_TOKEN`, `CLOUDFLARE_ACCOUNT_ID`; uploads all modules to **both** script names and health-checks each). Manual multipart deploys — two traps, both hit and verified:

- `bindings` omitted from upload metadata **silently drops them at runtime** — the settings API still lists them but `env.PLATFORM` is undefined (error 1101). Always re-send the full non-secret binding set.
- `secret_text` nuance (verified live 2026-09-25): a secret binding listed **without** `text` fails 10021, but a secret **omitted entirely** keeps its existing value — `env.PLATFORM_TOKEN` survived an upload that didn't list it. Omit secrets; never send them with empty text. `PLATFORM_TOKEN` = the worker bearer = `.env`'s `CLOUDFLARE_API_TOKEN`.
- **`wrangler deploy` on the product repo is a live-site breaker** (hit 2026-09-25): it uploaded assets-only (no `main` in `wrangler.jsonc`), dropped the `PLATFORM` service binding AND the `PLATFORM_TOKEN` secret — every API route 404'd, and after `main` was added, `kvPut` silently failed on platform auth (reports written-then-404'd). Recovery = `node scripts/deploy.mjs` + `wrangler secret put PLATFORM_TOKEN` on **both** script names. The repo's `wrangler.jsonc` now carries a warning comment; it exists only for `secret list/put`/`tail` tooling.
- Multipart part `filename=` is the module path — `-F "src/scanner.js=@src/scanner.js;filename=src/scanner.js"`, each with `;type=application/javascript+module`.
- **Full bundle (13 parts)** — `worker.js` + `src/{scanner,crawl,monitor,recommendations,validator,page,static}.js` + `src/rules/{additional,wcag22,section508,crosspage,focuscycle}.js`. Missing a part = runtime import failure (1101); stale extra parts are ignored.
